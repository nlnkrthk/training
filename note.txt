class Counter:

    def __init__(self):
        self.count = 1

    def __iter__(self):
        return self

    def __next__(self):
        if self.count <= 3:
            value = self.count
            self.count += 1
            return value
        raise StopIteration

def login(credentials: HTTPBasicCredentials = Depends(security)):

    username = secrets.compare_digest(
        credentials.username,
        "admin"
    )

    password = secrets.compare_digest(
        credentials.password,
        "admin123"
    )

    if not (username and password):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid Credentials",
            headers={"WWW-Authenticate": "Basic"},
        )

    return {
        "message": "Login Successful",
        "username": credentials.username
    }

OAuth-----
## OAuth (Open Authorization)

* **OAuth** is an **authorization protocol** that allows an application to access a user's data from another service **without knowing the user's password**.
* Used for **"Sign in with Google"**, **"Login with GitHub"**, **"Login with Microsoft"**, etc.
* The user logs in on the provider's website and grants permission to the application.
* The provider returns an **access token**, which the application uses to access allowed resources.
* Permissions are controlled using **scopes** (e.g., read email, read calendar).
* OAuth is mainly used for **third-party authentication and authorization**.

### OAuth Flow

```text
User
   ↓
Click "Login with Google"
   ↓
Google verifies user
   ↓
User grants permission
   ↓
Google returns Access Token
   ↓
Application uses token to access Google APIs
```

### OAuth vs JWT

* **OAuth** → Authorization protocol (how permission is granted).
* **JWT** → Token format (how user information/claims are stored and securely transmitted).

**For your FastAPI project:** ❌ OAuth is not required. A simple **JWT-based login** is sufficient.

bearer authentication----
from datetime import datetime, timedelta
from fastapi import Depends, FastAPI, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from jose import JWTError, jwt
from passlib.context import CryptContext
app = FastAPI()
SECRET_KEY = "mysecretkey123456789"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30
 
pwd_context = CryptContext(
    schemes=["bcrypt"],
    deprecated="auto"
)
oauth2_scheme = OAuth2PasswordBearer(
    tokenUrl="token"
)
fake_users_db = {
    "john": {
        "username": "john",
        "full_name": "John Smith",
        "email": "john@test.com",
        "hashed_password": pwd_context.hash("12345"),
    }
}
def verify_password(plain_password, hashed_password):
    return pwd_context.verify(
        plain_password,
        hashed_password
    )
 
def authenticate_user(username, password):
 
    user = fake_users_db.get(username)
 
    if not user:
        return None
 
    if not verify_password(
        password,
        user["hashed_password"]
    ):
        return None
 
    return user
def create_access_token(data: dict):
 
    to_encode = data.copy()
 
    expire = datetime.utcnow() + timedelta(
        minutes=ACCESS_TOKEN_EXPIRE_MINUTES
    )
 
    to_encode.update(
        {"exp": expire}
    )
 
    return jwt.encode(
        to_encode,
        SECRET_KEY,
        algorithm=ALGORITHM
    )
@app.post("/token")
 
def login(
    form_data: OAuth2PasswordRequestForm = Depends()
):
 
    user = authenticate_user(
        form_data.username,
        form_data.password
    )
 
    if not user:
 
        raise HTTPException(
            status_code=401,
            detail="Invalid username/password"
        )
 
    access_token = create_access_token(
        data={
            "sub": user["username"]
        }
    )
 
    return {
        "access_token": access_token,
        "token_type": "bearer"
    }
 
 
# -----------------------------------------
# Current User
# -----------------------------------------
 
def get_current_user(
    token: str = Depends(oauth2_scheme)
):
 
    credentials_exception = HTTPException(
        status_code=401,
        detail="Could not validate credentials"
    )
 
    try:
 
        payload = jwt.decode(
            token,
            SECRET_KEY,
            algorithms=[ALGORITHM]
        )
 
        username = payload.get("sub")
 
        if username is None:
            raise credentials_exception
 
    except JWTError:
        raise credentials_exception
 
    return fake_users_db.get(username)
 
 
# -----------------------------------------
# Protected API
# -----------------------------------------
 
@app.get("/profile")
 
def profile(
    current_user=Depends(get_current_user)
):
 
    return current_user

JWT (JSON Web Token)-----------
is a secure string that represents a user's identity.
Instead of asking the user to log in before every request, the server gives the user a token after they log in once.
The user then sends that token with every future reques
--process
User logs in with a username and password.
The server verifies the credentials against the database.
If they're correct, the server creates a signed JWT.
The client stores the JWT.
The client sends the JWT in the Authorization: Bearer <token> header with protected requests.
The server verifies the token's signature and expiration.
If the token is valid, the request is processed; otherwise, the server returns 401 Unauthorized.

unsupervised ml---
Unsupervised Learning is a type of machine learning in which the model learns patterns, structures, or relationships from unlabeled data. 
Unlike supervised learning, the dataset does not contain target/output labels.
The algorithm discovers hidden patterns or groups in the data on its own.

The main objective is to discover:

Similar groups (Clusters)
Hidden relationships
Patterns
Data structure
Outliers
Lower-dimensional representations

1 - clustering

Clustering is an unsupervised learning technique that groups similar data points into clusters based on their similarities, 
such that data points within the same cluster are more similar to each other than to those in other clusters.
    
- partition based - kmeans
 technique that groups unlabeled data into clusters based on similarity
Initialization: We begin by randomly selecting k cluster centroids.
Assignment Step: Each data point is assigned to the nearest centroid, forming clusters.
Update Step: After the assignment, we recalculate the centroid of each cluster by averaging the points within it.
Repeat: This process repeats until the centroids no longer change or the maximum number of iterations is reached.

- hierarchical - agglomerative
builds a hierarchy of clusters using a bottom-up approach. It starts by treating every data point as an individual cluster, 
then repeatedly merges the two most similar clusters until all data points belong to a single cluster or a stopping condition is met.
    Treat each data point as an individual cluster.
    Calculate the distance between all clusters and merge the two closest clusters.
    Recalculate the distances using a linkage method (Single, Complete, Average, or Ward) and repeat the merging process.
    Continue until one cluster remains or cut the dendrogram at the desired level to obtain the required number of clusters.
 
- density based - DBSCAN
groups together data points located in high-density regions and labels points in low-density regions as noise (outliers).
Unlike K-Means, it does not require the number of clusters (K) to be specified beforehand.
    Choose the values of ε (radius) and MinPts (minimum neighbors).
    Identify Core Points by checking if they have at least MinPts neighbors within ε.
    Expand clusters by connecting neighboring Core Points and including Border Points.
    Repeat until all points are processed, leaving isolated points as Noise (outliers). 
    
- distribution based - GMM
assumes the data is generated from a mixture of several Gaussian (Normal) distributions.
Instead of assigning each data point to exactly one cluster,
GMM calculates the probability that a data point belongs to each cluster and assigns it to the most probable one.
    Initialize the number of Gaussian distributions and their parameters (mean, variance, and mixing weights).
    Calculate the probability of each data point belonging to every Gaussian distribution (E-Step).
    Update the Gaussian parameters based on these probabilities (M-Step).
    Repeat the E-Step and M-Step until the parameters converge, then assign each point to the cluster with the highest probability.
    
- grid based
divides the entire data space into a fixed number of grid cells and performs clustering on these cells instead of individual data points. 
Dense grid cells are grouped together to form clusters, while sparse cells are ignored or treated as noise.
    Divide the feature space into equal-sized grid cells.
    Count the number of data points inside each grid cell.
    Identify dense cells using a predefined threshold.
    Merge adjacent dense cells to form clusters.

- model based
that assumes the data is generated from an underlying mathematical or statistical model. 
The algorithm tries to find the model that best explains the data and uses that model to identify clusters. 
    Assume a mathematical or statistical model that represents the data.
    Initialize the model parameters (e.g., means, variances, probabilities).
    Fit and update the model parameters to best explain the data.
    Assign each data point to the cluster (model) that best explains it after convergence.

2 - association rule learning
technique used to discover relationships, patterns, or associations between items in a dataset. 
It identifies which items frequently occur together and generates rules that describe these relationships.
    Collect transaction data and identify frequent itemsets based on a minimum support threshold.
    Generate association rules from the frequent itemsets.
    Evaluate each rule using Support, Confidence, and Lift.
    Select the strongest rules for analysis or recommendations.

reinforcement learning---
agent learns to make decisions by interacting with an environment and receiving rewards or penalties for its actions. 
The objective is to learn a strategy (called a policy) that maximizes the total cumulative reward over time.
| Term            | Meaning                        |
| --------------- | ------------------------------ |
| **Agent**       | Learner or decision-maker      |
| **Environment** | World the agent interacts with |
| **State**       | Current situation              |
| **Action**      | Decision taken by the agent    |
| **Reward**      | Feedback after an action       |
| **Policy**      | Strategy for choosing actions  |
| **Goal**        | Maximize cumulative reward     |


model based----
Model-Based Reinforcement Learning is an approach in which the agent knows or learns a model of the environment (how the environment behaves). 
Using this model, the agent predicts future states and rewards before taking an action.
- How It Works
Learn or obtain the environment model.
Predict the next state and reward for possible actions.
Choose the action that gives the highest future reward.
Execute the action and update the model if necessary.

model free----
Model-Free Reinforcement Learning is an approach in which the agent does not know or learn the environment model. 
Instead, it learns the best actions directly through trial and error using rewards received from the environment.

Overfitting occurs when a machine learning model learns not only the underlying patterns in the training data but also the noise and random fluctuations. 
As a result, it performs very well on the training data but poorly on new, unseen data.

evaluation metrics---

classification--
Classification Evaluation Metrics are measures used to evaluate how well a classification model predicts the correct class labels

-confusion matrix
|                     |  **Predicted Positive** |  **Predicted Negative** |
| ------------------- | ----------------------: | ----------------------: |
| **Actual Positive** |  **True Positive (TP)** | **False Negative (FN)** |
| **Actual Negative** | **False Positive (FP)** |  **True Negative (TN)** |


-accuracy
Accuracy measures the overall percentage of correct predictions made by the model.
Accuracy= TP+TN​
        TP+TN+FP+FN

-precision
Precision measures how many predicted positive cases are actually positive.
TP/TP+FP

-recall(sensitivity)
Recall measures how many actual positive cases were correctly identified.
TP/TP+FN

-f1 score
F1 Score is the harmonic mean of Precision and Recall.
F1=2×(PrecisionxRecall)
    (Precision+Recall​)


regression metrics--
Regression Evaluation Metrics are measures used to evaluate how accurately a regression model predicts 
continuous numerical values by comparing the predicted values with the actual values

MAE - MAE is the average of the absolute differences between the actual values and predicted values.
MAE = (1/n) * Σ|Actual - Predicted|


MSE -MSE is the average of the squared differences between the actual and predicted values.
MSE = (1/n) * Σ(Actual - Predicted)²

RMSE - RMSE is the square root of the Mean Squared Error (MSE).
It converts the squared error back to the original unit of the target variable.
RMSE = √MSE

R^2 score 
R² Score measures how much of the variation in the target variable is explained by the regression model.
R² = 1 - (SSres / SStot)
SSResidual = Sum of Squared Errors.
SSTotal = Total variation in the target values.


regularisation--
used to reduce overfitting by adding a penalty term to the model's loss (cost) function. 
This penalty discourages the model from learning overly complex patterns and helps it generalize better to unseen data.


cross validation---
A single train-test split may give unreliable results because the performance depends on one random split.
K-Fold Cross Validation evaluates the model on multiple splits, providing a more reliable estimate of its performance.

-k fold cross validation 
K-Fold Cross Validation evaluates the model on multiple splits, providing a more reliable estimate of its performance.
    Split the dataset into K equal folds.
    Train the model on K−1 folds and validate it on the remaining fold.
    Repeat until every fold has been used once as the validation set.
    Average the validation scores to obtain the final model performance.


-stratified k fold
Stratified K-Fold Cross Validation is a variation of K-Fold Cross Validation that ensures each fold has approximately the same class distribution as the original dataset. 
It is mainly used for classification problems, especially when the dataset is imbalanced.
